```text

```

## 5. ready / partial / excluded_v0 的当前含义

```text
ready
```

表示当前阶段认为该 kernel 的 OpenMP pragma 标注较完整，后续可以进入 correctness 与 trial 流程。

```text
partial
```

表示该 kernel 只安全并行化了一部分 loop，但仍有可测 OpenMP 行为。它不是失败状态，当前仍进入 correctness 与后续 trial。

```text
excluded_v0
```

表示 v0 阶段没有安全添加 OpenMP pragma，通常原因是 loop-carried dependence、三角求解、动态规划依赖或原地 stencil 依赖明显。当前不进入 correctness 与 trial。

## 6. LARGE_DATASET 是什么

PolyBench/C 的输入规模通常由编译期宏控制。常见选择有：

```text
MINI_DATASET
SMALL_DATASET
MEDIUM_DATASET
LARGE_DATASET
EXTRALARGE_DATASET
```

`LARGE_DATASET` 的意思是：编译时让 PolyBench 使用较大的预设问题规模。

例如同一个 kernel，在不同宏下数组维度和循环边界会不同：

```text
SMALL_DATASET       较小，运行快，但性能测量可能噪声大
MEDIUM_DATASET      中等规模
LARGE_DATASET       当前默认起点
EXTRALARGE_DATASET  更大，运行更久，采集成本更高
```

当前选择 `LARGE_DATASET` 的原因是：

```text
1. 它通常比 SMALL/MEDIUM 更能体现 OpenMP runtime 参数影响。
2. 它比 EXTRALARGE 更保守，避免一开始采集成本过高。
3. 项目文档要求默认从 LARGE_DATASET 开始，再根据 baseline runtime 自适应调整。
```

后续不会强制所有 kernel 永远使用 `LARGE_DATASET`。正式进入性能 trial 前，需要做 input size profiling：

```text
如果 LARGE_DATASET 太短，可以尝试 EXTRALARGE_DATASET。
如果 LARGE_DATASET 太慢，可以降到 MEDIUM_DATASET 或 SMALL_DATASET。
如果 runtime 落入目标窗口，则接受该规模。
```

当前建议目标窗口是：

```text
baseline median runtime: 0.5s - 30s
宽松接受范围: 0.2s - 60s
```

## 7. 当前新增脚本

当前新增了三个 dry-run-first 脚本：

```text
scripts/build_correctness_binaries.py
scripts/generate_reference_outputs.py
scripts/check_correctness.py
```

它们默认不真正执行编译或运行，只有加 `--execute` 才会执行。

### 7.1 build_correctness_binaries.py

作用：

```text
从 original/ 编译 sequential reference binary。
从 omp_v0/ 编译 OpenMP correctness binary。
```

默认处理：

```text
ready + partial kernels
```

跳过：

```text
excluded_v0 kernels
```

### 7.2 generate_reference_outputs.py

作用：

```text
运行 sequential reference binary。
保存 live-out array dump。
生成 reference correctness oracle。
```

这一步会真实运行程序，但不是正式性能跑分。

### 7.3 check_correctness.py

作用：

```text
运行 OpenMP binary。
使用 canonical baseline OpenMP 环境。
将 OpenMP live-out dump 与 sequential reference dump 做数值比较。
```

默认比较容差：

```text
abs_tol = 1e-6
rel_tol = 1e-5
```

这一步会真实运行 OpenMP 程序，并且 canonical baseline 使用 `OMP_NUM_THREADS=64`。因此 CPU 忙时不建议执行。

## 9. CPU 空闲后建议执行顺序

CPU 空闲后，建议先 dry-run：

```bash
python3 datasets/polybench_runtime_v0/scripts/build_correctness_binaries.py --dataset-macro LARGE_DATASET
python3 datasets/polybench_runtime_v0/scripts/generate_reference_outputs.py --dataset-macro LARGE_DATASET
python3 datasets/polybench_runtime_v0/scripts/check_correctness.py --dataset-macro LARGE_DATASET
```

确认 kernel 数量、路径、输出位置正确后，再执行：

```bash
python3 datasets/polybench_runtime_v0/scripts/build_correctness_binaries.py --dataset-macro LARGE_DATASET --execute
python3 datasets/polybench_runtime_v0/scripts/generate_reference_outputs.py --dataset-macro LARGE_DATASET --execute
python3 datasets/polybench_runtime_v0/scripts/check_correctness.py --dataset-macro LARGE_DATASET --execute
```

其中：

```text
第一条主要是编译，不是性能跑分。
第二条会运行 sequential 程序，不是性能跑分，但会占用 CPU。
第三条会运行 OpenMP 程序，默认 OMP_NUM_THREADS=64，会明显占用 CPU。
```

因此当前 CPU 仍有其他任务时，建议等待再执行第二条和第三条。
